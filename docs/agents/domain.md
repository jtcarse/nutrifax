# Domain docs

Use a single-context layout: `GLOSSARY.md` at the repo root and ADRs in `docs/adr/`.

Before exploring domain code, read `GLOSSARY.md` if it exists and relevant ADRs in `docs/adr/`. These files can be created when terms or decisions are resolved; their absence does not block work.

Use glossary terms when naming domain concepts in issues, code, tests, and proposals. If a needed term is missing, check the project's language and record a genuine gap for domain modeling.

Surface any proposed change that conflicts with an existing ADR, naming the ADR and explaining the conflict.
